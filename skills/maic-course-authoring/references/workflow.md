# 工作流 SOP

从源材料到可导入的 `.maic.zip` 的完整流程。每一步都标明用哪个 MCP 工具、
产出什么、以及什么情况下必须停下来回退。

前置：确认 MCP 的工具可用。若某个工具不存在，停下来告诉用户，不要用猜测代替。

---

## 阶段 0 · 材料入库

```text
1. material_list                          → 看清有哪些材料、各自字符数
2. material_read(materialId, offset=0)    → 逐页读完，记下结构（章节、页码边界）
3. material_search(关键概念)               → 抽查若干关键词，确认检索可用
```

**产出**：一份内部材料地图（每个材料有哪些章节、大致字符区间）。

**门禁**：材料为空或无法读取 → 停止，告知用户。**绝不在无材料的情况下继续**，
用户忘传附件时，模型通常仍会继续生成——这一步的门禁就是为此设的。

---

## 阶段 1 · 规划

先写"讲什么"，再决定"放几页"。

```text
1. 从材料地图提炼主题与核心概念
2. 划分教学单元（每个单元 = 一个可讲清的知识块）
3. 为每个单元分配 1-3 页
4. 决定每页类型：slide / quiz / interactive / pbl
5. 决定是否插测验（建议每 3-5 页一次）
6. 写出页面清单：order、type、title、一句话目的、对应的材料出处
```

**产出**：页面清单（内部工作稿，不必交付）。

**门禁**：清单里每一项都必须能指向材料中的某个部分；指不上的项要么删掉，
要么明确标记为"补充知识"。见 `grounding.md` 规则 2。

**页数纪律**：页数服从材料容量。宁可 12 页讲透，不要 50 页灌水。

---

## 阶段 2 · 逐页写作

一次写一页，写一页校验一页。不要攒到最后一起校验。

每页的步骤：

```text
1. material_search / material_read        → 回原文取该页要用的具体片段
2. 查 dsl_schema_get 的 requiredFields     → 以返回的必需字段表为准
3. 按 slide-craft 的版式规则排版：
   - 画布 1000 × 562.5，50px 边距（live area [50,950] × [50,512.5]）
   - 字号查表定高度
   - 对齐网格：左对齐 left=60/80；居中 (1000-width)/2
4. 按 slide-dsl 的字段规则写 elements
5. 写 actions（讲解词、聚光灯等），见 actions 参考
6. draft_normalize                         → 补默认值、派生可派生的几何
7. draft_validate                          → 只校验这一页
8. 修掉所有 error，再进入下一页
```

**关键提醒（来自 `slide-craft`，这些是渲染事实不是建议）**：

- `<ul>` / `<ol>` 在播放时**没有项目符号**，要写成一 `<p>` 一行、符号写进文本
  （`<p style="font-size:18px;">• 要点</p>`）
- `<h1>`–`<h6>` 是**惰性的**（`font-size: inherit`），字号只能靠内联 `font-size`，
  加粗只能靠 `<strong>`
- 纯文本里的换行**不生效**，多行必须写成真正的多个 `<p>`
- 文本元素有 10px padding，容器高度不够时文字**溢出而不是缩放**
- 字号写在 content HTML 里，没有 `font-size` 字段

---

## 少写字：不要逐字重画版式

一份 20 页的课件如果每页都从头写坐标和样式，既慢又容易出错，而且版式会不一致。
上游对此有两个明确的机制，本 MCP 都实现了：

### `scene_clone` —— 克隆已有页面的版式

**这是多页课件的默认做法**：先把**一页**做好（版式、字号、对齐都调好），
后续页面用 `scene_clone` 复制它，只改写文字槽位。

```text
scene_clone({
  manifest,
  fromOrder: 1,                    // 复制哪一页
  title: '新的页面标题',
  newOrder: 3,                     // 插到哪（省略则追加到末尾）
  replacements: [
    { find: '原来的标题文字', replace: '新的标题文字' },
    { find: '原来的要点一',   replace: '新的要点一' }
  ]
})
```

规则：

- 每个 `find` 必须在该页内**恰好出现一次**。出现 0 次或多次都会报错——
  这是刻意的，防止你改错地方。扩大锚点让它唯一即可。
- 某条旁白的文字被改写时，它的 `audioRef` 会被**自动移除**并告警，
  因为原音频已经和新文字不匹配了。
- 原本就有的 `id`/`mediaRef` 等会被继承，媒体引用不用重写。

先读一遍源页确认原文（用 `find` 之前先知道它在不在），再克隆。

### `draft_normalize` —— 让上游补默认值

元素内容有一批必需默认值（`defaultFontName`、`defaultColor`、`fill` 等），
以及可以派生的几何（`line` 的 `start`/`end`、`shape` 的 `viewBox`/`path`）。
这些**不用你写**：先只写最小必需字段，调 `draft_normalize` 让上游填。

注意它**不会**填 `id` / `left` / `top` / `width` / `height` / `rotate`——
这些必须显式写。

推荐顺序：`写最小字段 → draft_normalize → draft_validate`。
一次不要攒太多页，一页一页过。

---

## 阶段 3 · 成稿校验

```text
1. material_search(每个数字/公式/专有名词)   → 逐个回原文核对
2. draft_validate                            → 校验整份文档
3. 走一遍 grounding.md 的自检清单
```

**门禁**：自检清单任何一项为"否"→ 回到阶段 2 修，不要进入打包。

---

## 阶段 4 · 打包与交付

```text
1. draft_validate                           → 结构 + id 唯一性 + 引用完整性
2. draft_layout                             → 版式：越界 / 溢出 / 折行 / 压盖
3. scene_normalize_ids                      → id 加页前缀并去重（长课程必跑）
4. course_pack_maic_zip                     → 产出 .maic.zip
5. 向用户交付，并说明：
   - 这份课件依据了哪些材料
   - 哪些部分材料未覆盖（已标注为补充）
   - 是否有材料无法解析/被截断
   - 导入方式：OpenMAIC 首页 → 导入课堂 → 选择 .maic.zip
```

### 结构之外的四类缺陷

结构校验通过不等于课件没问题。以下是结构闸门抓不到、但会在真实交付里炸掉的四类
缺陷，以及对应的检查工具：

| 缺陷 | 症状 | 工具 |
| --- | --- | --- |
| **元素 id 重复** | 渲染层报重复 key，页面反复重渲染 | `draft_validate`（id 唯一性）、`scene_normalize_ids`（修复） |
| **元素越出安全区** | 内容被裁掉或压到页边 | `draft_layout` |
| **文本盒高度不足** | 文字溢出容器、压到下一块内容 | `draft_layout` |
| **元素互相压盖** | 文字被图片/表格盖住 | `draft_layout` |

其中 id 重复最隐蔽：**同一页调用两次同一个版式函数，两批元素的 id 会从同一个起点
开始**（两处都是 `el_step1`），此时每页结构都合法、整份文档的 schema 校验也全绿，
只有渲染时会坏。规则：

- 元素 / 动作 / 题目 id **全篇唯一**；表格单元格 id 在元素内唯一。
- 长课程交付前必跑一次 `scene_normalize_ids`，它给全部 id 加 `p{页码}_` 前缀并去重，
  同时把 `spotlight` / `laser` 的 `elementId` 改指新 id。
- 重命名元素之后，记得同步引用它的动作。

### 逐页出处对照表（SOURCES.md）

交付时随包给一份 **SOURCES.md**，逐页列出：这一页讲了什么、依据材料哪一段、
配图来自哪里。它的价值在两件事上：

1. 用户可以抽查任意一页的依据，而不必通读材料；
2. 材料本身有缺陷时（残句、重复用字、**正文与截图不一致**），在这里如实记录，
   课件里只保留可确定的部分，不做补写。

材料里"正文说 4 位、截图显示位数 5"这类自相矛盾，不要替材料做决定——
参数表用正文的值，另加一行说明截图取值，并问用户想要哪种。

### 配图可以直接从源 PDF 提取

课件配图最可靠的来源是**源材料本身**：从 PDF 里按页提取系统截图，逐张打开确认
内容与对应章节相符，再压缩到合适的宽度（1440px 足够），登记进 `mediaIndex` 并随包
提供字节。这比让 Agent 画示意图可靠得多，也避免了"图是真的、配文是编的"的风险。

**每张图都要人工核验后再配上**：截图与正文不一致（版本差异、界面更新）时，
以截图为准还是以正文为准，记进 SOURCES.md 并问用户。

### 长课程：用共享版式函数保证一致性

20 页以上的课件不要每页手写坐标。先写一个装配器（版式函数）统一维护
stage / canvas / theme 骨架、页头位置、卡片尺寸、动作 id 编号，然后每页只提供
**内容**——标题、要点、配图、讲解词。这样：

- 多页版式自动一致，不会出现"第 3 页标题在 60、第 17 页标题在 72"；
- 改一处版式，全篇生效；
- id 由装配器统一编号，天然避开撞 id 的问题。

`scene_clone` 解决"复用一页已有版式"；装配器解决"从零批量产出一致的版式"。
两者不冲突：先定版式函数，个别特殊页再用克隆微调。

### 交付前做一次视觉抽查

结构校验与版式检查都过了，仍然值得生成一份本地近似预览（把每页元素按
left/top/width/height 画到 HTML 里）并快速过一遍。它的价值在于能抓到
校验器抓不到的**"元素被静默丢弃"**类 bug——比如装配函数只接受了一种形态的入参，
导致配图和表格根本没进页面。这类问题在数据层面完全合法，只有看见才知道。

## 迭代：用户反馈后怎么改

用户说"第 3 页改成 XX"时：

1. **只改被点名的那一页**，不要顺手重写其他页。
2. 改之前先 `material_read` / `material_search` 确认新内容的出处。
3. 改动后 `draft_validate` 只校验该页，再校验整份文档。
4. 重新打包。

不要为了"整体更协调"而重生成全部页面——那是把错误放大的经典方式。

---

## 反模式清单

以下做法一律禁止：

- ❌ 材料缺失时靠模型先验硬编内容
- ❌ 用"大纲 → 摘要 → 再摘要"的多跳方式传递信息（每跳都会稀释原文依据）
- ❌ 写完一整份再统一校验
- ❌ 数字凭记忆写，不逐字核对
- ❌ 为凑页数灌水
- ❌ 把 `keyPoints` 之类的中间摘要当原文依据
- ❌ 用猜测的 `src` 占位符（会永远显示骨架屏，见 `maic-zip.md`）
- ❌ 自称"根据材料"但实际没有回链原文
