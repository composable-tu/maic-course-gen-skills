# 原文保真规则

这是本 Skill 存在的理由。请把这一节当作**高于一切其他规则**的约束。

## 为什么需要它

OpenMAIC 自带的生成流水线为**吞吐与一致性**做了明确取舍：

> 用户材料的文本在大纲阶段读一次，之后各阶段基于大纲继续展开。

这是一个合理的设计——它让很少的模型调用就能产出结构稳定的课件。代价是：
从大纲往后，模型手里只剩上一阶段的产物，不再有原文可比对。

两条路线的差异在于材料在哪一步进入模型上下文。本仓库选了「全程依据原文」，
于是保真需要单独的流程来保证：

- 提示词模板里，只有大纲阶段的三个模板带 `{{pdfContent}}`：
  `requirements-to-outlines`、`interactive-outlines`、`task-engine-outlines`。
- 下游模板（`slide-content`、`quiz-content`、`simulation-content`、
  `diagram-content`、`code-content`、`game-content`、`procedural-skill-content`、
  `visualization3d-content`）的入参是 `title` / `description` / `keyPoints`。
- 类型层也印证这一点：`OutlinePromptContext` 有 `pdfText`，而 `SceneContentOptions`
  没有该字段。
- 再往后一跳更远：`SceneGenerationContext` 只有 `pageIndex` / `totalPages` /
  `allTitles` / `previousSpeeches`，讲解稿是从**已生成的幻灯片元素**再生成的。
- 大纲阶段的输入上限为 `MAX_PDF_CONTENT_CHARS = 50_000`（多文档经
  `allocateDocumentTextBudgets` 分配预算后按词边界截断）。

所以在我们这条链上：`原文 → 大纲 → 场景内容 → 讲解稿`，每一跳的输入都是上一跳的
产物。**没有回链原文的环节，也就没有了 ground truth 可比对**——因此"我不太确定"
这件事在下游是难以察觉的。

**唯一天然存活的是图片**（大纲阶段作为 vision 附件，并经 `assignedImages` 进到场景
内容阶段）。这解释了最典型的症状：**图是真的，配文是编的。**

## 我们的做法

内容由 Agent 亲自撰写，保真责任在我们这一侧，需要用流程来保证。四条硬规则：

### 规则 1：先建索引，再写任何内容

开始写作之前，必须先对全部源材料建立可检索的索引。用 MCP 的
`material_search` 逐条验证索引可用。

不允许"我记得材料里提到过"——必须能给出命中的原文片段。

### 规则 2：每个事实性断言都要有出处

凡是数字、公式、专有名词、日期、引文、结论，写之前必须 `material_search`
或在已读片段中确认。写作时在内部工作稿里保留出处（页码 / 字符偏移 / 原文片段），
交付物里不必带引用，但你要能回答"这句话来自哪里"。

无法找到出处的，只有两个合法选择：

1. **删除该断言**；
2. **明确标注为补充知识**（例如在讲解词里说"这一点材料里没有展开，补充一个背景"），
   并确保它不与材料冲突。

**绝不能**把一个猜测写成像材料里的内容一样确定。

### 规则 3：宁可留白，不要填空

材料没有覆盖的大纲条目，应当缩减小节、缩短页面，或在讲解词里显式说明材料未涉及。
不要为了"填满 50 页"而把模型的先验知识伪装成材料内容。
页数服从材料，不是材料服从页数。

### 规则 4：数字与公式逐字核对

数字、单位、量级、公式符号是最容易被"顺手改写"的东西，也是最容易毁掉整份课件
可信度的东西。写完后必须逐个回原文核对，**不要依赖记忆**。

特别注意以下高风险改写：数量级（万 / 亿 / billion）、单位（% / pp / 百分点）、
年份、版本号、下标与上标、正负号、以及带歧义的中文数量表述。

## 自检清单

交付前逐条确认，任何一条为"否"就不要交付：

- [ ] 每个数字/公式/专有名词都能在材料中定位到原文
- [ ] 大纲中每个条目都能追溯到材料的某个部分，或已明确标注为补充知识
- [ ] 没有"材料未提及但被当成材料内容陈述"的断言
- [ ] 页面数量与材料容量相称，没有为凑篇幅而填充
- [ ] 讲解词与页面内容一致（讲解词不得引入页面上没有、材料里也没有的新事实）
- [ ] 图与文一致（图片应来自材料或与材料内容相符，不得图不对文）
- [ ] 材料被截断/无法解析的部分已在交付说明中告知用户

## 风险提示：代价在后移

在这条链上，错误一旦进了正文，后续每一跳都会把它当作既定事实，而且越说越具体、
越说越笃定——因为之后的上下文里已经没有任何东西能"反驳"它。
**错误在大纲层是廉价的，在讲解稿层是昂贵的。** 所以核对要在写作时做，不是交付后做。
